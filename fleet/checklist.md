# Preservation checklist — site/index.html (Mythic+ Performance dashboard)

Contract every rebuilt version must satisfy. One numbered line per item: what it is, where it lives today (line refs are into `site/index.html`), what it does, and what it couples to. "Live-verified" notes come from the running mirror (data of 2026-08-25: hasTimed=true, hasTier=true, hasRating=true, hasTune=false, hasProj=false, keys 2–19, two week buckets).

## A. Page shell, loading & data contract

1. Single-file page: all CSS/JS inline; only external requests are Google Fonts (Cinzel display + Inter body, preconnect links, L8–10) and the data payload — rebuilds must not add other network dependencies.
2. `<title>` starts as "Mythic+ Performance — Midnight" (L11) and is rewritten after load to `"Mythic+ Performance — "+(d.season||"Midnight")` (L689); live: "Mythic+ Performance — Midnight Season 2".
3. Favicon is an inline SVG data-URI ⚔️ emoji (L7); meta robots index,follow; viewport meta present.
4. Dark gold-on-charcoal theme via `:root` custom properties (--bg #15171C, --gold #F8B700, class-colored accents etc., L13–22); fixed radial-gradient body background; custom scrollbars; gold `:focus-visible` outline; gold `::selection`.
5. Layout: CSS grid `300px 1fr` with a full-height sidebar rail painted by a background gradient trick (L41–44); sidebar is `position:sticky; top:0; height:100vh; overflow-y:auto` at ≥901px; collapses to single column ≤900px (sidebar no longer sticky, main padding shrinks).
6. Main column: `max-width:1200px; margin:0 auto` so content floats mid-viewport on wide screens (L134); `#chart{max-width:960px}` caps bar width (L189).
7. Loading state: `#loading` spinner row "Loading data…" shown while fetching; `#app` and `#side` (aside) are `display:none` until data arrives; on fetch failure `#loading` text becomes "Failed to load data: "+error (L585) and the app never shows.
8. Data source config `SEASON` (L554–560): `file:"data.json"`, sub-line text, footer source text, `minchars:250`, `maxchars:1200` — the sub goes to `#hero-sub`, foot to `#foot-src`, minchars/maxchars to the slider.
9. `loadJSON(file)` (L564–577): if `DecompressionStream` exists, first fetch `file+".gz"` with `{cache:"no-cache"}` and inflate through `new DecompressionStream("gzip")`; only if the .gz response is not ok (or no DecompressionStream) fall back to plain `fetch(file,{cache:"no-cache"})`, throwing `"HTTP "+status` on failure. The no-cache is deliberate (GitHub Pages max-age=600; conditional 304s keep it fresh) — preserve both the .gz-first order and cache:no-cache on both requests.
10. Payload shape consumed: `d.rows` columnar arrays (dps, run, cls, spec, hero, dun, key, day, deaths, role, reg, char, optional tier/timed/post/tmul/dur/kdur), plus `d.classes/specs/heroes/dungeons/regions/roles`, `d.epoch` (day-0 date), `d.built`, `d.season`, optional `d.charscore`, `d.tuning`, `d.projection`, `d.pars` (per-dungeon timer). `N = R.dps.length`; `runCount = max(R.run)+1` (L590–592).
11. Derived `R.atk` Int8Array: 1 = melee, 2 = ranged, 0 = neither, from the hardcoded `MELEE`/`RANGED` sets of "Class|Spec" keys (L463–473) — these sets are data, preserve their exact membership (incl. e.g. Paladin|Holy as melee, DemonHunter|Devourer).
12. `CLASS_COLORS` map (L458–462) — exact WoW class hex colors incl. `Unknown:"#999999"`; used by chart bars, trend lines, class dots, comp spans.
13. Cascading option maps built once per dataset: `clsSpecs` (class → set of specs seen) and `csHeroes` ("Class|Spec" → set of hero talents seen, excluding "Unknown") (L594–603).
14. Feature flags detected from the payload, each hiding its UI when absent: `hasTier` (any `R.tier ≥ 0` → `#tierbox` shown, L612–613), `hasRating` (any charscore ≥ 0 → rating tabs/columns), `hasTune` (`d.tuning && R.post` → `#tunebox`), `hasProj` (`D.projection && R.tmul` → `#projbox`), `hasTimed` (any `R.timed ≥ 0` → `#timedseg`) (L612–642). Live: tier/rating/timed on; tune/proj off.
15. Selections carried over between sources are pruned to names that still exist (`prune` of cls/spec/hero/dun/reg against the new payload, L644–647).
16. Per-load defaults (L649–694): weeksA={0} if bucket 0 has data else the newest bucket with data; weeksB={first bucket >0} else the only bucket; dayCut=0; key range khi = max(kmax−1, kmin), klo = max(khi−5, kmin) (six-wide band ending one below the highest logged key — live: +13–+18 of 2–19); minchars=250 with slider max 1200; compare off (`$("cmp").checked=false`); tier checkboxes wired and set from state (tier4 true by default); `DEF` snapshot {klo,khi,timedOnly,postTune} taken HERE as the minchars yardstick; `refMemo` cleared; ends with `setCompare(false)` which also renders.
17. `state` defaults (L516–533) that matter beyond the above: role={"DPS"}, merge=true, timedOnly=true→overwritten to hasTimed, postTune=true→overwritten to hasTune, tier0/2=false, tier4=true, pctl=50, elite=false, sort="desc", tab="med", trendMetric="avg" (note: applyArchonState later sets it to "med"), trendView="lines", compMin=20, csort={strength,-1}, ssort={pt,-1}, tsort={a_v,-1}.
18. Reset-week bucketing `computeResetBuckets()` (L786–817): per-region reset boundary from `RESET_RULES {US:[Mon-based weekday 1, 15h UTC], EU:[2,4]}` else `RESET_DEFAULT [2,22]`; each row gets `R.rbucket` = 0 for current reset, k for k resets ago, 999 for undated (day<0); `usB0` = US current-reset start day (fallback: first region) anchors all week labels; `weekCounts` Map(bucket→parse count) and sorted `availWeeks` drive every week chip; `curMinDay/curMaxDay` = day span of bucket-0 data (curMaxDay anchors the elite 14-day window).
19. `periodCut`/`periodPass` plumbing (L820–828): day-zoom UI was removed (`paintDays(){}` no-op, L937) but `dayCut` stays 0 and `periodCut()` inert — call sites all still pass through it; a rebuild may keep or drop this, but `periodPass(i,weeks,cut)` semantics (empty weeks set = no filter; membership by rbucket) must survive.
20. `RUNS` built once per dataset (L757–781): one entry per run with dur/kdur/dun/key/day, summed deaths, and the 5-player comp sorted Tank→Healer→DPS then class then spec; `key_` = comma-joined `cls*100+spec` ids (comp identity); `pct` = timer margin `(par−kdur)/par*100` using `D.pars[dun]`, null when par or kdur missing — feeds Top Comps only.
21. `fmtDay` renders epoch-relative day numbers as "Aug 25" en-US UTC (L550); `fmtDur` as m:ss (L782); `fmtInt` as en-US thousands-grouped integers (L548); `esc()` escapes & and < for every user-facing dynamic string.
22. `window.addEventListener("resize")` re-renders only when the Trend tab is active (SVG width depends on box width, L717).

30. Spec chips: union of specs of the selected classes (all specs when no class selected); selection further narrows the Hero pool (`heroPool()` walks class×spec pairs through `csHeroes`, L838–845).
31. Hero Talent chips: inside `#hero-box`, which is `display:none` whenever "Merge hero talents into spec" is checked (L993–994) — hero selection still exists in state but `rowPass` only applies the hero mask when `!state.merge` (L1183).
32. "Merge hero talents into spec" checkbox, default checked (L311): drives `state.merge`; flips grouping key (`groupKey` = cls*100+spec when merged, ×200+hero when not, L1190–1192), shows/hides the Hero Talent box, adds/removes the "Hero Talent" column in the Breakdown and Set Bonus tables, and changes the Breakdown sub-line wording ("Class / Spec" vs "Class / Spec / Hero Talent"). Un-merging deliberately does NOT rescale the min-chars threshold (comment L1196–1202).
33. All checkbox inputs inside `label.small` render as sliding pill switches via pure CSS (appearance:none track+knob, gold when checked, L74–86) — this is the visual identity of merge/melee/ranged/tier/cmp/archon/posttune/proj toggles.

## D. Sidebar — Archon mode

34. "Archon mode" switch (`#archon`, L306–310) with bold label, a long `title` tooltip describing the replica scope ("Keys 12–19 … percentile 90 … ρ≈0.95 … Unchecks itself the moment any of those settings moves." — note the title text predates the current p85/per-spec-floor implementation; preserve it verbatim or consciously update it) and an inline hint: "replicate archon.gg's high-keys table — per-spec elite key floor, p85, last 14 days".
35. Turning Archon ON (L1067–1074): first `archonPrev=snap()` — snapshot of {pctl, elite, klo, khi, timedOnly, tier0/2/4, merge, compare, tab, trendMetric, role[], weeksA[]} (L1062–1066) — then `applyArchonState({pctl:85, elite:true, klo:min key, khi:max key, timedOnly:false, tier0/2/4:false, merge:true, compare:false, tab:"med", trendMetric:"med", role:["DPS"], weeksA:ALL buckets with data})`. Key range and weeks are parked at full range on purpose: the elite path bypasses them, and mid-range values would misleadingly suggest they apply (comment L1019–1024). Live-verified: pctl→85, keys→+2–+19, weeks→{0,1}, timed→All completed, all tier boxes off, med tab relabels "p85 DPS".
36. `applyArchonState(st)` (L1039–1061) is the single writer for both directions: Object.assigns the scalar settings (always forcing `dayCut:0`), replaces `state.role`/`state.weeksA` sets, then syncs EVERY affected control — merge/cmp/tier checkboxes, pctl slider + label, med TAB label via `dpsLabel()`, timed segmented buttons, `setCompare(state.compare)` (shows/hides block B and gain/loss sort buttons, renders), `buildControls()` (rebuilds chips/sliders/tabs), `refreshPeriodUIs()`, re-marks the active `#tabs` and `#trendseg` buttons and refreshes their med labels, then `render()`.
37. Turning Archon OFF explicitly (L1075–1084) restores `archonPrev` wholesale via `applyArchonState`, falling back (if archonPrev is somehow null) to a hardcoded default {elite:false, pctl:50, klo:12, khi:19, timedOnly:hasTimed, tier0/2:false, tier4:true, merge:true, compare:false, tab:"med", trendMetric:"med", role:[], weeksA:[0]}; then `archonPrev=null`. Restore returns to whatever existed at toggle-ON time (live-verified).
38. Archon checkbox is DERIVED state: every `render()` begins by computing `__archonMatches()` and setting `am.checked=ok`; if the predicate fails while `state.elite` is true, `state.elite` is silently cleared (L1449–1453) — so moving ANY covered setting auto-unchecks the mode and drops back to standard statistics while KEEPING the user's changes (no snapshot restore on this path; live-verified: nudging pctl to 90 unchecked it, left keys/weeks/timed parked).
39. `__archonMatches()` predicate (L1026–1033): `state.elite && pctl===85 && klo===min key && khi===max key && !timedOnly && !tier0 && !tier2 && !tier4 && merge && !compare && role.size===1 && role.has("DPS")`. Note what it does NOT check: weeksA, postTune, class/spec/hero/dungeon/region selections, sort, tab — those can be changed freely inside the mode without exiting it.
40. `state.elite` selects the dedicated `aggregateElite()` path inside `aggregate()` (L1314–1315); only the mode toggle sets elite, only the render-time predicate clears it.
41. `aggregateElite()` (L1242–1312), constants `ELITE_KEEP=0.10, ELITE_PCTL=0.85, ELITE_MIN=50, ELITE_DAYS=14`: window = last 14 days anchored on `curMaxDay` (falling back to max `R.day`); its row filter applies ONLY day-window, projSkip, class/spec/(hero when unmerged)/dungeon/role/melee-ranged/region masks — it BYPASSES the key clamp, period buckets, timed-only, post-tune, tier filters and the min-characters gate (all deliberate; comment L1231–1241 records the validation: Spearman 0.960, median level ratio 1.01 vs archon.gg).
42. Elite pass 1: per-group key histogram (Uint32Array(40), keys capped at 39); groups with <50 rows get no floor; else the floor is the highest key level where the cumulative count from the top reaches ≥10% of the group's rows (L1261–1274).
43. Elite pass 2: keep rows with `key ≥ floor` for their own group; accumulate the same group stats as the normal path plus `floorK`; groups whose qualifying (post-floor) parse count is <50 are dropped and counted in `eliteHidden` ("thin elite pool: hide, never guess", L1296–1299).
44. Elite group output: `med = qp(dps, 0.85)` — hard-coded p85 regardless of slider (the predicate pins the slider to 85 anyway); avg/adeaths/deathless/chars/runs computed on the elite pool; `arating/mrating = NaN, rn = 0` (ratings intentionally absent in elite mode — table shows "–"); ravg/rmed only under projection.
45. Elite period-note line (L1499–1503): "⚔ Archon replica: per spec, the top decile of key levels, then p85 DPS within — the moving elite frontier their table tracks. Key/period/min-character controls are bypassed while active" plus, when eliteHidden>0, "; N spec(s) hidden for having under 50 qualifying parses".
46. Min-chars gate skipped in elite mode: the row join keeps every elite group (`if(!state.elite && a.chars<effMinA && …) continue`, L1474) — yet `#minchars-eff` still shows the scaled "→ ≥ N here" text (harmless; live-verified showing "≥ 124 here" while bypassed).

## E. Sidebar — role / melee–ranged / tier

47. Role chips: fixed list ["DPS","Healer","Tank"] (L944); default selection {DPS}; empty = all roles; feeds the role mask in both normal and elite paths and — with melee/ranged — is one of the two knobs that `refChars()` honours in the min-chars reference.
48. Melee / Ranged checkboxes (L314–318) with hint "both/neither = no filter": XOR semantics — `atk` mask is 1 (melee) or 2 (ranged) only when exactly one is checked (`state.melee!==state.ranged`, L1154, L1209).
49. Tier filter row `#tierbox` (L319–324), shown only when `hasTier`: three switches — "No set bonus" (`t0`), "Season 2 2-piece" (`t2`), "Season 2 4-piece" (`t4`, DEFAULT ON) — plus live `#tierhint` text.
50. `setBucket(t)` (L1174): −1 for unknown gear (t<0), 0 = fewer than 2 tier pieces ("no set"), 1 = 2–3 pieces ("2-set only, NOT 4"), 2 = 4+ pieces. Buckets are deliberately disjoint so ticking multiple boxes is a union, and cohorts are comparable (comment L1156–1173).
51. `tierPass(i)` (L1161–1170): always true when `!hasTier` (so a gear-less payload with tier4 defaulted on doesn't blank the page); true when no box is ticked; otherwise parses with unknown gear (t<0) are EXCLUDED ("unknown, not 'no set'"), and the parse passes iff its bucket's box is ticked.
52. `#tierhint` (`updateTierHint`, L1631–1645): computed across rows passing the CURRENT period + all filters except the tier boxes themselves (`rowPass(i,m,true)`): "gear known for X.X% of parses in view (N)", appending " — thin here; the backfill covered +12 and up" when <10%; empty when nothing in view. Live: "gear known for 81.2% of parses in view (60,197)".

## H. Sidebar — Quality

65. "Minimum characters" slider (L349–352): range 1–`cfg.maxchars` (1200), default 250; gold value readout `#minchars-v`; oninput updates state + readout and renders.
66. `#minchars-eff` inline annotation: shows "→ ≥ N here" (localized number) only when the effective scaled threshold differs from the slider value (L1467–1468); the effective value also appears in the Breakdown sub-line and the chart empty-state message.

In compare mode each period scales by its own chars pool (`effMinA`/`effMinB`, L1465).

## R. Non-obvious behavior contracts (must-not-lose summary)

145. `render()` is the single pipeline (L1448+): archon predicate sync → aggregate A (and B when comparing) → effective min-chars → join/gate rows → KPIs → period note → seg visibility → renderComps → (Trend branch: renderTrend + renderTable + renderSetBonus + updateTierHint + early return) → chart → caption → renderTable → renderSetBonus → updateTierHint. Rebuilds must keep every surface refreshing on every state change.
146. `rowPass(i,m,anyTier)` filter order/semantics (L1175–1189): postTune, timedOnly, tier (skipped when anyTier=true — used by Set Bonus and the tier hint), key clamp, class, spec, hero (only when unmerged), dungeon, role, melee/ranged, region. Elite mode replaces this wholesale (see item 41).
147. Aggregate group stats (normal path, L1314–1368): n (parses), sum/avg, med = qp at slider percentile, adeaths, deathless% (share of zero-death parses), distinct chars, distinct runs (parses ≠ runs: two same-spec players in one run = 2 parses, 1 run), ratings computed over the distinct CHARACTER set (a 200-run grinder counts once; unrated chars drop out; rn = rated count), recorded ravg/rmed kept only under projection.
148. Percentile-0 edge: pctl slider bottoms at 0 ("worst parse") — `qp(sorted,0)` = minimum; label becomes "p0 DPS"; nothing special-cases it. Slider tops at 99, never 100.
149. Tab/label mutation is stateful: the med entry of the module-level `TABS` array is mutated by the pctl handler and applyArchonState — any rebuild keeping a static tab config must still relabel the med tab everywhere (tabs, trendseg) live, without a full control rebuild.
150. `state.trendPin`, `state.tsort`, `state.ssort`, `state.csort`, collapse state, and all filter sets survive re-renders; only a page reload (the Reset button) clears them. Archon on/off (via buildControls) rebuilds chips but reuses the same state sets, so selections survive entering/leaving the mode.
151. Sorting defaults + fallbacks: Breakdown {a_v,−1}→(compare?a_v:avg); Set Bonus {pt,−1}; Comps {strength,−1} — each validated against the current column set every render so a column that disappears (e.g. hero column after re-merging) can't strand the sort.
152. Every dynamic count/number rendered to the page uses `fmtInt` (en-US grouping) or the specific fixed-decimals formats listed per surface; dates always via `fmtDay` (UTC, en-US "Mon D").
153. The chart/table/tooltip trio must agree: the same gated `rows` array feeds chart and Breakdown; Groups-compared KPI equals its length; tooltips are built from the same row objects.
154. Deleted-report projection rows (tmul=0) are excluded from every statistic while projecting — including refChars and Set Bonus — never only from one side.
155. `q50` (exact median, L1143) is used for Set Bonus cell medians and rating medians; `qp` (interpolated) for the percentile metric — both must be preserved as distinct functions (they differ on even-length arrays).
156. XSS discipline: every payload-derived string (class/spec/hero/dungeon names, tuning labels, projection labels) passes through `esc()` before innerHTML insertion.
157. The page renders correctly with any optional payload feature absent: no timed → seg hidden + timedOnly false; no tier → tier UI, Set Bonus section, tier note all gone and tierPass inert; no ratings → rating tabs/columns/tooltip rows gone; no tuning/projection → their toggles hidden and filters off. Rebuilds must gate on the same has* flags, not assume the live payload's shape.
