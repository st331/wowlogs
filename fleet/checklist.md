# Preservation checklist — site/index.html (Mythic+ Performance dashboard)

Contract every rebuilt version must satisfy. One numbered line per item: what it is, where it lives today (line refs are into `site/index.html`), what it does, and what it couples to. "Live-verified" notes come from the running mirror (data of 2026-08-25: hasTimed=true, hasRating=true, hasTune=false, hasProj=false, keys 2–19, two week buckets).

## A. Page shell, loading & data contract

1. Single-file page: all CSS/JS inline; only external requests are Google Fonts (Cinzel display + Inter body, preconnect links, L8–10) and the data payload — rebuilds must not add other network dependencies.
2. `<title>` starts as "Mythic+ Performance — Midnight" (L11) and is rewritten after load to `"Mythic+ Performance — "+(d.season||"Midnight")` (L689); live: "Mythic+ Performance — Midnight Season 2".
3. Favicon is an inline SVG data-URI ⚔️ emoji (L7); meta robots index,follow; viewport meta present.
4. Dark gold-on-charcoal theme via `:root` custom properties (--bg #15171C, --gold #F8B700, class-colored accents etc., L13–22); fixed radial-gradient body background; custom scrollbars; gold `:focus-visible` outline; gold `::selection`.
5. Layout: CSS grid `300px 1fr` with a full-height sidebar rail painted by a background gradient trick (L41–44); sidebar is `position:sticky; top:0; height:100vh; overflow-y:auto` at ≥901px; collapses to single column ≤900px (sidebar no longer sticky, main padding shrinks).
6. Main column: `max-width:1200px; margin:0 auto` so content floats mid-viewport on wide screens (L134); `#chart{max-width:960px}` caps bar width (L189).
7. Loading state: `#loading` spinner row "Loading data…" shown while fetching; `#app` and `#side` (aside) are `display:none` until data arrives; on fetch failure `#loading` text becomes "Failed to load data: "+error (L585) and the app never shows.
8. Data source config `SEASON` (L554–560): `file:"data.json"`, sub-line text, footer source text, `minchars:250`, `maxchars:1200` — the sub goes to `#hero-sub`, foot to `#foot-src`, minchars/maxchars to the slider.
9. `loadJSON(file)` (L564–577): if `DecompressionStream` exists, first fetch `file+".gz"` with `{cache:"no-cache"}` and inflate through `new DecompressionStream("gzip")`; only if the .gz response is not ok (or no DecompressionStream) fall back to plain `fetch(file,{cache:"no-cache"})`, throwing `"HTTP "+status` on failure. The no-cache is deliberate (GitHub Pages max-age=600; conditional 304s keep it fresh) — preserve both the .gz-first order and cache:no-cache on both requests.
10. Payload shape consumed: `d.rows` columnar arrays (dps, run, cls, spec, hero, dun, key, day, deaths, role, reg, char, optional timed/post/tmul/dur/kdur), plus `d.classes/specs/heroes/dungeons/regions/roles`, `d.epoch` (day-0 date), `d.built`, `d.season`, optional `d.charscore`, `d.tuning`, `d.projection`, `d.pars` (per-dungeon timer). `N = R.dps.length`; `runCount = max(R.run)+1` (L590–592).
11. Derived `R.atk` Int8Array: 1 = melee, 2 = ranged, 0 = neither, from the hardcoded `MELEE`/`RANGED` sets of "Class|Spec" keys (L463–473) — these sets are data, preserve their exact membership (incl. e.g. Paladin|Holy as melee, DemonHunter|Devourer).
12. `CLASS_COLORS` map (L458–462) — exact WoW class hex colors incl. `Unknown:"#999999"`; used by chart bars, trend lines, class dots, comp spans.
13. Cascading option maps built once per dataset: `clsSpecs` (class → set of specs seen) and `csHeroes` ("Class|Spec" → set of hero talents seen, excluding "Unknown") (L594–603).
14. Feature flags detected from the payload, each hiding its UI when absent: `hasRating` (any charscore ≥ 0 → rating tabs/columns), `hasTune` (`d.tuning && R.post` → `#tunebox`), `hasProj` (`D.projection && R.tmul` → `#projbox`), `hasTimed` (any `R.timed ≥ 0` → `#timedseg`) (L612–642). Live: rating/timed on; tune/proj off.
15. Selections carried over between sources are pruned to names that still exist (`prune` of cls/spec/hero/dun/reg against the new payload, L644–647).
16. Per-load defaults (L649–694): weeksA={0} if bucket 0 has data else the newest bucket with data; weeksB={first bucket >0} else the only bucket; dayCut=0; key range khi = max(kmax−1, kmin), klo = max(khi−5, kmin) (six-wide band ending one below the highest logged key — live: +13–+18 of 2–19); minchars=250 with slider max 1200; compare off (`$("cmp").checked=false`); Gear axis off (`state.gear=false; state.ilob=0; state.ihib=0;` — 0 = B not set yet, so `buildControls` clamps B only once it has been set; 2026-09-18, §AA); `DEF` snapshot {klo,khi,timedOnly,postTune,ilo,ihi} taken HERE as the minchars yardstick (ilo/ihi = the full item-level range, so `refChars` only applies an item-level clause when the default itself is narrowed, i.e. never — the Gear axis rewrites the slider, never DEF; see 204); `refMemo` cleared; ends with `setCompare(false)` which also renders.
17. `state` defaults (L516–533) that matter beyond the above: role={"DPS"}, merge=true, timedOnly=true→overwritten to hasTimed, postTune=true→overwritten to hasTune, pctl=50, elite=false, sort="desc", tab="med", trendMetric="avg" (note: applyArchonState later sets it to "med"), trendView="lines", compMin=20, csort={strength,-1}, tsort={a_v,-1}.
18. Reset-week bucketing `computeResetBuckets()` (L786–817): per-region reset boundary from `RESET_RULES {US:[Mon-based weekday 1, 15h UTC], EU:[2,4]}` else `RESET_DEFAULT [2,22]`; each row gets `R.rbucket` = 0 for current reset, k for k resets ago, 999 for undated (day<0); `usB0` = US current-reset start day (fallback: first region) anchors all week labels; `weekCounts` Map(bucket→parse count) and sorted `availWeeks` drive every week chip; `curMinDay/curMaxDay` = day span of bucket-0 data (curMaxDay anchors the elite 14-day window).
19. `periodCut`/`periodPass` plumbing (L820–828): day-zoom UI was removed (`paintDays(){}` no-op, L937) but `dayCut` stays 0 and `periodCut()` inert — call sites all still pass through it; a rebuild may keep or drop this, but `periodPass(i,weeks,cut)` semantics (empty weeks set = no filter; membership by rbucket) must survive.
20. `RUNS` built once per dataset (L757–781): one entry per run with dur/kdur/dun/key/day, summed deaths, and the 5-player comp sorted Tank→Healer→DPS then class then spec; `key_` = comma-joined `cls*100+spec` ids (comp identity); `pct` = timer margin `(par−kdur)/par*100` using `D.pars[dun]`, null when par or kdur missing — feeds Top Comps only.
21. `fmtDay` renders epoch-relative day numbers as "Aug 25" en-US UTC (L550); `fmtDur` as m:ss (L782); `fmtInt` as en-US thousands-grouped integers (L548); `esc()` escapes & and < for every user-facing dynamic string.
22. `window.addEventListener("resize")` re-renders only when the Trend tab is active (SVG width depends on box width, L717).

37. Turning Archon OFF explicitly (L1075–1084) restores `archonPrev` wholesale via `applyArchonState`, falling back (if archonPrev is somehow null) to a hardcoded default {elite:false, pctl:50, klo:12, khi:19, timedOnly:hasTimed, merge:true, compare:false, tab:"med", trendMetric:"med", role:[], weeksA:[0]}; then `archonPrev=null`. Restore returns to whatever existed at toggle-ON time (live-verified), the Gear axis included: `archonPrev` carries `gear/ilob/ihib/gearPrev`, so the axis, both cohorts, the restore memory, `#blockG` and the "B: ilvl lo–hi" chip come back (`if("ilob" in st){state.ilob=st.ilob; state.ihib=st.ihib;}`; the hardcoded fallback has no `gear` → off). The silent exit (item 38) leaves gear off with B still in state and the memory parked (null), so a later fresh activation starts clean (item 212). Verified 2026-09-18 by `scratchpad/chk_gear.py` (park: gear false, A 29–371, `#cmpseg.dis`, `__archonMatches()` true; restore: gear true, A 322–371, B 29–321, chip "B: ilvl 29–321"; Off after the round trip restores A to any).
38. Archon checkbox is DERIVED state: every `render()` begins by computing `__archonMatches()` and setting `am.checked=ok`; if the predicate fails while `state.elite` is true, `state.elite` is silently cleared (L1449–1453) — so moving ANY covered setting auto-unchecks the mode and drops back to standard statistics while KEEPING the user's changes (no snapshot restore on this path; live-verified: nudging pctl to 90 unchecked it, left keys/weeks/timed parked).
39. `__archonMatches()` predicate (L1026–1033): `state.elite && pctl===85 && klo===min key && khi===max key && !ilvlNarrowed() && !timedOnly && merge && !compare && !gear && role.size===1 && role.has("DPS")` (`!gear` added 2026-09-18, §AA; `skill` is not checked — `archonTarget` parks both axes off and `#cmpseg` is `.dis` inside the mode, so only a snapshot restore can bring one back). Note what it does NOT check: weeksA, postTune, class/spec/hero/dungeon/region selections, sort, tab — those can be changed freely inside the mode without exiting it.
40. `state.elite` selects the dedicated `aggregateElite()` path inside `aggregate()` (L1314–1315); only the mode toggle sets elite, only the render-time predicate clears it.
41. `aggregateElite()` (L1242–1312), constants `ELITE_KEEP=0.10, ELITE_PCTL=0.85, ELITE_MIN=50, ELITE_DAYS=14`: window = last 14 days anchored on `curMaxDay` (falling back to max `R.day`); its row filter applies ONLY day-window, projSkip, class/spec/(hero when unmerged)/dungeon/role/melee-ranged/region masks — it BYPASSES the key clamp, period buckets, timed-only, post-tune and the min-characters gate (all deliberate; comment L1231–1241 records the validation: Spearman 0.960, median level ratio 1.01 vs archon.gg).
42. Elite pass 1: per-group key histogram (Uint32Array(40), keys capped at 39); groups with <50 rows get no floor; else the floor is the highest key level where the cumulative count from the top reaches ≥10% of the group's rows (L1261–1274).
43. Elite pass 2: keep rows with `key ≥ floor` for their own group; accumulate the same group stats as the normal path plus `floorK`; groups whose qualifying (post-floor) parse count is <50 are dropped and counted in `eliteHidden` ("thin elite pool: hide, never guess", L1296–1299).
44. Elite group output: `med = qp(dps, 0.85)` — hard-coded p85 regardless of slider (the predicate pins the slider to 85 anyway); avg/adeaths/deathless/chars/runs computed on the elite pool; `arating/mrating = NaN, rn = 0` (ratings intentionally absent in elite mode — table shows "–"); ravg/rmed only under projection.
45. Elite period-note line (L1499–1503): "⚔ Archon replica: per spec, the top decile of key levels, then p85 DPS within — the moving elite frontier their table tracks. Key/item-level/period/min-character controls are bypassed while active" (the "item-level/" part only when `ILVL.has`, item 206) plus, when eliteHidden>0, "; N spec(s) hidden for having under 50 qualifying parses". No compare sentence can share the line: `#cmpseg` is `.dis` in the mode, `setGear` returns early on `state.elite`, and `archonTarget` parks the Gear axis off (2026-09-18, §AA).
46. Min-chars gate skipped in elite mode: the row join keeps every elite group (`if(!state.elite && a.chars<effMinA && …) continue`, L1474) — yet `#minchars-eff` still shows the scaled "→ ≥ N here" text (harmless; live-verified showing "≥ 124 here" while bypassed).
